# Правила приоритизации Главной FocusFlow

## 1. Источники событий

Главная собирает состояние четырёх направлений:

- **Задачи:** один кандидат, выбранный алгоритмом «Следующий шаг».
- **Привычки:** только привычки, запланированные на сегодня.
- **Проекты:** незавершённые этапы с указанным сроком.
- **Финансы:** сводка из того же расчёта прогноза, который используется в панели «Финансы».

## 2. Приоритеты событий

Чем выше число, тем раньше событие попадает в блок «Что важно сегодня».

| Приоритет | Событие | Условие |
|---:|---|---|
| 100 | Критический финансовый риск | Прогноз финансов имеет статус `red` |
| 95 | Просроченный этап проекта | Этап не завершён, срок строго раньше сегодняшней даты |
| 90 | Высокий финансовый риск | Прогноз финансов имеет статус `orange` |
| 88 | Застрявшая задача с результатом | Нет фиксаций результата более 7 дней |
| 82 | Задача проекта с близким сроком | Задача связана с проектом, дата — сегодня или в ближайшие 3 дня |
| 80 | Просроченная задача | Дата задачи раньше сегодняшней |
| 70 | Приоритетная задача | Пользователь явно отметил задачу приоритетной |
| 65 | Риск потери серии привычки | Привычка запланирована сегодня, не отмечена, текущая серия больше нуля |
| 55 | Обычная следующая задача | Других более важных условий нет |

Если одновременно существует несколько событий, в блоке показывается событие с наибольшим приоритетом. При равном приоритете просроченные этапы рассматриваются в порядке самой ранней даты.

## 3. Отдельный алгоритм «Следующего шага»

Сначала выбирается задача-кандидат:

1. Застрявшие задачи с измеримым результатом.
2. Задачи проекта со сроком не позднее 3 дней от сегодняшней даты, включая просроченные.
3. Задачи, явно отмеченные пользователем как приоритетные.
4. Задачи с частичным результатом.
5. Остальные незавершённые задачи — по ближайшей дате.

При одинаковой дате более давно обновлявшаяся задача располагается выше. Причина выбора показывается пользователю. Кнопка «Другая задача» переключает кандидата, не меняя данные задачи.

Обычные задачи без измеримого результата не получают бейдж «Застряла».

## 4. Правила предупреждений

- Финансы: предупреждение создаётся только для `orange` или `red`. Статусы `yellow`, `green` и `gray` не являются предупреждением.
- Проекты: этап становится проблемой только после наступления просрочки. Само приближение срока не является предупреждением.
- Привычки: риск показывается только в запланированный день, если серия уже существует и сегодняшняя отметка ещё не сделана.
- Предупреждения являются отражением текущего состояния, а не повторяющимися push-уведомлениями. Событие остаётся видимым, пока проблема не устранена или не перестала быть актуальной.

## 5. Ручная проверка

1. **Финансы:** установить прогноз в `red`, убедиться, что финансовое событие выше остальных. Повторить для `orange`. При `yellow` финансовое предупреждение не должно появляться.
2. **Проект:** создать этап со вчерашним сроком и не завершать его — Главная должна показать просрочку. Этап со сроком сегодня не должен считаться просроченным.
3. **Привычка:** создать привычку с серией, запланированную на сегодня, и не отмечать её — Главная должна предупредить о риске. После отметки предупреждение исчезает. Привычка без серии не должна создавать предупреждение.
4. **Застрявшая задача:** создать задачу с числовой целью, зафиксировать частичный результат, затем проверить задачу с датой последней фиксации старше 7 дней. Она должна получить бейдж и подняться в «Следующем шаге».
5. **Обычная задача:** задача без измеримого результата не должна получать бейдж «Застряла».
6. **Продолжение:** создать продолжение по кнопке. Оно должно показывать связь с исходной задачей; пока продолжение активно, исходная задача не должна повторно помечаться как застрявшая.
7. **Переключение:** при нескольких открытых задачах кнопка «Другая задача» должна менять кандидата и объяснение причины.
8. **Четыре направления:** Главная должна показывать четыре строки-сводки: задачи, привычки, проекты и финансы. Подробные списки остаются в своих панелях.
